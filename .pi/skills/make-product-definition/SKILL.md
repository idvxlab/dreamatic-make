# Prototype Product Definition

Distinguish an appearance model, an interaction demonstration, and a standalone functional prototype first. This determines which functions need real implementation and which may explicitly use placeholders.

Record users, scenarios, key tasks, controls and feedback, size limits, budget and currency, purchasing region, printer and material, and assembly capabilities. Keep assumptions and questions explicit. Only gaps that change the solution need to block downstream work.

Translate vague goals into acceptance methods. For example, switching among three data pages with a knob requires an input, state transition, and observable result. Mark undefined response time or accuracy as pending confirmation; never invent measured values.

Give mechanical design actionable form intent: proportions, grip or placement, interface position, and accepted or rejected directions. Compare candidates without prematurely fixing unverified boards or hole locations.

Save product entries and hand off functional priorities, manufacturing constraints, and specific pending decisions. Reference prior entries and explain impact when requirements change; preserve unaffected goals.
